# Fincept Terminal — Python scripts

The Python half of the terminal: data connectors, analytics, AI agents and
backtesting providers. The C++ application (Qt) runs them as subprocesses; none
of them is imported by C++.

## How a script runs

- `src/python/PythonRunner` starts `python <script> <command> [args...]` with
  this folder as the working directory and on `PYTHONPATH`. At most three run at
  once (the rest queue). A watchdog kills a run after 5 minutes, or 60 minutes
  for `vision_quant/`, `ai_quant_lab/`, `agents/` and `Analytics/backtesting/`.
- Two virtual environments are managed by `PythonSetupManager` (uv):
  - `venv-numpy2` — the default, from `resources/requirements-numpy2.txt`
    (first run installs only `requirements-numpy2-core.txt`);
  - `venv-numpy1` — any script whose path contains `vectorbt`, `backtesting`,
    `gluonts`, `functime`, `pyportfolioopt`, `financepy` or `ffn`, from
    `resources/requirements-numpy1.txt`.
  Editing a requirements file is enough: installed environments re-sync when
  its hash changes.
- **Output contract.** Print one JSON document on stdout. On failure print
  `{"error": "<message>"}` — PythonRunner treats it as a failure even on exit
  code 0. Never print `NaN` or `Infinity` (Qt's JSON parser rejects the whole
  document); emit `null`. Logs go to stderr.
- **Secrets and large payloads go on stdin** (a `--stdin` flag), never argv:
  any process running as the same user can read a command line, and Windows
  caps it at ~32 KB. API keys saved in Settings arrive as environment variables
  (`kManagedCredentialKeys` in `PythonRunner.cpp`, plus
  `src/config/KeyedConnectorCredentials.inc`).
- `yfinance_data.py` also runs as a long-lived daemon (`PythonWorker`) that
  serves quotes, sparklines and history without a new process per call.

## Who runs the scripts

1. **C++ services** in `src/services/**`. Screens never start Python themselves
   (`CLAUDE.md` rules D1/P6).
2. **The Data Sources catalogue.** Every `*_data.py`, plus the extra scripts
   named in `connector_overrides.json`, is listed in
   `resources/data_connectors.json`, generated by
   `.github/scripts/gen_data_connectors.py`. Any listed command can be run from
   Data Sources › Catalog and from workflow data-source nodes.
3. **AI agents, through MCP.** The `python` core tool
   (`src/mcp/core/PythonScriptTool.cpp`) lists every script that has an
   `if __name__ == "__main__":` block. Its module docstring is what an agent
   reads, so name the commands and their arguments there. Tests, `_tools/`,
   `i18n/` and files starting with `_` or `test_` are never runnable that way;
   `exchange/`, `agents/`, `voice/`, live strategies and order- or
   money-moving commands ask the user first.

## Layout

| Path | What it holds |
|---|---|
| `*_data.py` (~200) | Data connectors: macro and central banks, government statistics, markets, crypto, energy and climate, shipping, geospatial. Per-category docs in the `*_DATA_SOURCES.md` files. |
| `yfinance_data.py` | Market data: quotes, history, company info, financials, news, search; also the daemon above. |
| `Analytics/` | Corporate finance (M&A, LBO, DCF, startup valuation, fairness opinions), economics, fixed income, alternative investments, portfolio management, options analytics, library wrappers (ffn, Fortitudo, functime, GluonTS, gs-quant, statsmodels, PyPortfolioOpt, pypme, py_vollib) and the backtesting providers (VectorBT, Backtesting.py, Zipline, BT, Fincept). |
| `strategies/` | Strategy library run by the Fincept backtesting provider (`_registry.py`, engine in `fincept_engine/`). |
| `ai_quant_lab/` | Qlib and RD-Agent research tools behind the AI Quant Lab screen. |
| `agents/` | Agent frameworks (`finagent_core/`, `deepagents/`, `rdagents/`) and the persona configs in `EconomicAgents/`, `GeopoliticsAgents/`, `TraderInvestorsAgent/`. |
| `exchange/` | Crypto exchange daemon and WebSocket stream (ccxt). |
| `fincept_mcp/` | SEC EDGAR research (`edgar/`) and the stdio bridge for external MCP clients. |
| `vision_quant/`, `voice/` | Chart-image similarity search; speech-to-text, text-to-speech and clap detection. |
| `fincept_json.py`, `sdmx_json.py` | Shared helpers (NaN-safe JSON output, SDMX-JSON parsing). |

## Already in C++ — do not add Python for these

These moved to C++ for speed and reliability; their Python versions are gone:

- option implied volatility and Greeks — `src/services/options/OptionPricing`
- the Derivatives calculators (bonds, YTM, options, FX, swaps, CDS) —
  `src/services/options/DerivativesPricing`
- technical indicators (Equity Research and the workflow node) —
  `src/services/equity/TechnicalIndicators`
- TOTP codes — `src/core/crypto/Totp`
- prediction-market odds for the News screen — `src/services/news/NewsCorrelationService`
- news sentiment (VADER + finance lexicon), entity extraction, headline
  geolocation, nearby-infrastructure lookup and translation —
  `src/services/news/NewsNlpEngine`, `VaderSentiment`, `NewsNlpService`

## Adding a data source

1. Create `<source>_data.py`: a module docstring that names every command, a
   `main()` that dispatches on `sys.argv[1]`, JSON on stdout and
   `{"error": ...}` on failure.
2. Read API keys from environment variables. If the connector cannot work
   without its key, record `key_required` for it in `connector_overrides.json`
   (the generator refuses a keyed connector without that decision).
3. Run `python .github/scripts/gen_data_connectors.py` from the repository root
   and commit the regenerated `resources/data_connectors.json` and
   `src/config/KeyedConnectorCredentials.inc`.
4. If a screen needs the data, call it from a C++ service, not the screen.

New packages go into the matching requirements file with a pinned version.
Anything in `requirements-numpy2-core.txt` must also appear in
`requirements-numpy2.txt` with the same specifier. Check that the set still
resolves with `uv pip compile <file> --python-version 3.11 --python-platform
<platform>` for Windows, Linux and macOS.
